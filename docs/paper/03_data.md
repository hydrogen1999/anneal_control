# 3. Data and protocol

## 3.1 Two instance populations

| | synthetic | Pegasus-240 |
|---|---|---|
| topology | generated hardware-like graphs | **real Pegasus connectivity** |
| logical parents | 240 | 240 |
| records | 4 320 | 2 880 |
| splits (parents) | 144 / 48 / 48 | 144 / 48 / 48 |
| logical sizes | 3 – 5 | 5 – 7 |
| physical qubits | 3 – 10 | 10 – 14 |
| runtimes | 1, 4, 12 | 4, 12 |
| instance families | spin glass, weighted max-cut, planted loops, weak field | the same four, balanced |
| stored candidates | 64 | 64 |
| resolved spectral response | 0.799 | **0.0** |

A third population, an earlier 96-parent Pegasus set with 12 held-out parents,
is retained as a **replication target** rather than superseded data (§5.3).

The last row matters twice. It is why the auxiliary-physics arm can be tested
on the synthetic set and not on either Pegasus set (§7.3), and it is why one
cell of the Pegasus contrast matrix is a degeneracy rather than a measurement.

## 3.2 The candidate library

Each record stores 64 candidate schedules with simulator-evaluated losses: one
linear ramp, three one-window and two two-window slow regions, two pauses, and
56 low-discrepancy samples of feasible duration logits. **The waveforms are
identical across every record**, verified by hash — the library is a fixed
object, not an instance-specific search result.

This library is, in the design protocol, a device for *generating labels*:
store every result, not only the winner. We also use it as the method's action
space, and §6 measures what that choice is worth by varying how much of it the
critic may see.

## 3.3 Splitting, and what is held out

All embeddings, gauges, chain-strength variants and runtimes of one logical
instance stay in the same split. Held-out means **a logical problem the model
has never seen in any embedding**, which is the generalisation a deployment
actually needs, and a stricter condition than holding out records.

Test-split *search* is online adaptation and is not used to train or select
anything. Where a search appears in this paper it is a denominator (§5.2),
carries `online_adaptation: true` on every row, and is never ranked against an
amortised method.

## 3.4 Statistics

Every headline number is a mean of **parent means** with a bootstrap over
parents. Families of comparisons are corrected: the encoder contrast covers all
ten pairs of five encoders and is Holm-corrected as one family, with
uncorrected intervals reported alongside so the correction is auditable.

Two conventions we state because they change what a reader should conclude:

- **Pooling over training seeds** happens before the statistics, so reported
  win rates are pooled. Where the worst single seed differs we say so — the
  synthetic 48/48 is 47/48 in its least favourable seed, while the Pegasus
  48/48 holds in *every* seed.
- **Failure to separate is not equivalence.** Non-rejection sets are reported
  as sets, never as claims of equality.

## 3.5 Reproducibility

Every number in this paper is regenerated from committed record-level outcomes
by one script, and a `--check` mode fails on drift between the committed
artifacts, the analysis code, and the reported tables. Datasets carry a source
fingerprint; a dataset generated by different code is refused rather than
silently reused.
