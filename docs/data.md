# Dataset generation and integrity contract

The generator creates compiled Hamiltonians and accepted numerical outcomes;
it does not promise that randomly generated instances are difficult, that a
planted endpoint produces a small quantum gap, or that a synthetic graph is a
commercial hardware topology.

## Configuration

Existing schema-1 configurations remain valid. Schema-1 records generated by
older releases remain readable. New optional configuration keys are below.

| Key | Contract |
|---|---|
| `logical_qubits: 3` | One logical size; legacy form. |
| `logical_sizes: [3, 4]` | Multiple sizes, taking precedence over `logical_qubits`; balanced round-robin family-size cells. |
| `chain_lengths: [2, 2, 2]` | Fixed lengths; requires one element per logical variable. |
| `chain_lengths: 2` | Repeat a fixed length for every variable, including multiple logical sizes. |
| `chain_distribution` | Alternative to `chain_lengths`, never specify both. Fields: `distribution`, `low`, `high`, optional `exponent`. |
| `logical_support` | Fields: `kind`, optional `edge_probability`; defaults to complete support. |
| `generation_route` | `synthetic_lift` (default) or `hardware_growth`. |
| `hardware` | For hardware growth, inline `n_qubits` and undirected `edges` in zero-based dense labels. |
| `split` | Optional `holdout_families`, `holdout_sizes`, `validation_fraction`, `test_fraction`. |
| `teacher` | `mode: exact`, `adaptive`, or `none`, plus appropriate teacher options. |
| `candidate_batch_size` | Number of simultaneous controls of one Hamiltonian; default 1. |
| `h_limit`, `j_limit` | Positive symmetric programmed coefficient caps; defaults 2 and 1. Not vendor autoscale. |
| `endpoint_max_qubits` | Exact acceptance/enumeration cap, never more than 20. |
| `endpoint_memory_mb` | Per-worker conservative endpoint allocation budget in MiB. |
| `state_memory_mb` | Per-worker conservative state/batch allocation budget in MiB. |
| `endpoint_chunk_size` | Exact spin enumeration batch size; default 16384. |

For a multi-size example, use these **changes to a complete base config**:

```json
{
  "parents": 24,
  "logical_sizes": [3, 4],
  "families": ["spin_glass", "weighted_maxcut"],
  "chain_distribution": {
    "distribution": "power_law", "low": 1, "high": 2, "exponent": 2.0
  },
  "logical_support": {"kind": "connected_erdos_renyi", "edge_probability": 0.45},
  "max_physical_qubits": 8,
  "teacher": {"mode": "adaptive", "max_queries": 33, "audit_points": 5},
  "candidate_batch_size": 4
}
```

Remove the base config's `chain_lengths` when adding `chain_distribution`.
The example is not a recommended final experimental distribution: choose that
distribution using the pre-registered difficulty/control-headroom study.

### Support distribution is explicit

- `complete`: every pair is available.
- `path`, `cycle`: a shuffled labelled path or cycle; cycles require at least 3 nodes.
- `erdos_renyi`: unconditioned G(n,p), possibly disconnected.
- `connected_erdos_renyi`: independently sample ER edges, then add a shuffled
  path backbone. This is **not** ER conditioned on connectivity.

All coefficients and supports are sampled before spectral/dynamics outcomes.
Frustrated-loop parents require a cyclic support. Invalid planting supports and
exact duplicate coefficient problems are retried deterministically, at most
128 attempts. Records report the accepted attempt. This conditions the parent
distribution on valid planting support and exact uniqueness; report it when
describing the dataset. An impossible support configuration fails explicitly.

### Chain lengths and fixed hardware

The discrete `power_law` (alias `powerlaw`) uses mass proportional to
`length ** (-exponent)` on the finite inclusive range `[low, high]`.
Uniform sampling uses equal mass over that same range. Length vectors are
rejected if their sum exceeds the physical budget (and hardware capacity if
provided), so the joint distribution is **conditioned on the budget**, not
unrestricted independent power-law draws. Target lengths and rejection counts
are retained. At most 1024 vector draws are attempted.

`synthetic_lift` realizes exact requested lengths using a controlled toy graph.
It reports identical target/achieved lengths; it does not use real topology.

`hardware_growth` seeds disjoint chains on the supplied graph, extends chains
through free adjacent qubits, and contracts the resulting partition to a
logical support. It may jam before reaching requested lengths. Records retain:

- target and achieved chain lengths, plus `target_met`;
- original hardware labels for the active physical register;
- unused hardware qubit count;
- the generated quotient logical problem.

Each hardware partition belongs to one parent. The parent split is assigned
before strength/runtime/coefficient-distribution variants are emitted.
Regrowing another partition is **not** called another embedding of the same
logical parent. For hardware growth, variant `shape`/`ports` do not modify the
fixed partition; `variant_geometry_applicable` is false. Use coefficient
distribution variants if desired, and do not inflate sample size by repeating
identical variants. Synthetic variants do apply their shape and port settings.

## Splits and duplicate audit

With one size and no explicit `split`, the original family-stratified split is
preserved. With multiple sizes, each family-size cell is independently split.
Use at least 3 parents per retained cell when both validation and IID test
fractions are positive. The implementation rejects cells that cannot leave a
training parent after allocation; it does not silently move variants across
splits.

All parents in a requested held-out family **or** size go to test. Other cells
still have an IID test subset unless `test_fraction: 0` is selected. For a pure
size holdout, for example:

```json
{"split": {"holdout_sizes": [5], "validation_fraction": 0.2, "test_fraction": 0.0}}
```

Train, validation, and test must all remain nonempty. A logical parent and all
its variants always share one split. No outcome, spectrum, or success metric
is consulted when allocating splits.

The exact labelled structural fingerprint hashes logical `h`, sorted edges,
and correspondingly sorted `J`, with floating signed zero normalized. Parent
IDs, family names, and provenance metadata are excluded from this fingerprint.
Duplicate fingerprints under distinct parent IDs are rejected. The loader
also checks that one parent ID never changes logical coefficients. This is
**not graph-isomorphism or gauge-equivalence detection**: relabelled/equivalent
problems may remain, so report this limitation and extend the audit before
making stronger novelty or cross-instance-independence claims.

## Teachers and exact output labels

`teacher.mode: exact` retains the original fixed grid in `[0.02, 0.98]`. Every
query is a full capped dense eigendecomposition. Stored labels include moment
masks, frequency masses, residuals, rank/near-degeneracy information. There is
no interpolation certificate.

`teacher.mode: adaptive` starts with `spectral_points` equally spaced queries
covering `[0, 1]`, including the endpoints. Other options pass to
`adaptive_spectral_profile`: `max_queries`, `audit_points`,
`relative_tolerance`, `absolute_tolerance`, `min_interval_width`,
`residual_tolerance`, and `orthogonality_tolerance`. The per-path seed is derived
from the dataset seed/fingerprint, not supplied as another teacher seed.
Adaptive training queries and independent audit queries are distinct. Compact
held-out audit labels and diagnostics are retained in metadata, while only
adaptive training queries populate `response_*`. `max_queries` includes the
reserved audit queries. Budget exhaustion does not invent interpolated labels;
valid individually computed labels remain and diagnostics report unresolved
intervals. Even passing sampled checks are not a uniform certificate. See
[teacher.md](teacher.md).

Both complete spectral modes are limited to **10 physical qubits**. Adaptivity
reduces the number of queries, not the exponential cost of each query.

`teacher.mode: none` disables spectral queries. Moment arrays are placeholders
with every `response_mask` entry false, and frequency-bin arrays have zero
columns. These zeros must never be treated as supervised targets. Outcome
labels are still independently simulated and accepted by the same convergence
checks. For more than 10 physical qubits, configuration must explicitly include
`endpoint_max_qubits`, `endpoint_memory_mb`, and `state_memory_mb`; exact output
acceptance is never silently replaced by a proxy. The physical cap remains 20.
Exact spin enumeration is chunked, but exponential runtime and retained output
vectors remain. This is not a polynomial-scale simulator.

Compilation validation enumerates exact logical/physical endpoint energies in
chunks, checks the aligned energy identity, and reports whether an aligned
physical ground state exists. Weak chains that violate aligned-ground presence
are retained and marked. Output success accepts every physical string whose
majority-decoded logical string is an exact logical optimum, including broken
chains that decode correctly. Ties decode to +1; this is not generally gauge
invariant.

## Execution, convergence, and resumability

Python API:

```python
from annealctrl.pipeline import generate_dataset, load_records

manifest = generate_dataset(config, "runs/dataset", workers=4, backend="numpy")
train_records = load_records("runs/dataset", "train")
```

When called from a custom script with `workers > 1`, put the call inside
`if __name__ == "__main__":` because workers use Python's spawn context. The
provided CLI is already safe. CPU workers own independent parents and output
files. The coordinating process writes the manifest in deterministic parent
order. Worker count is not part of the scientific fingerprint. Numerical
records are equal across worker counts under the same numerical environment;
elapsed costs/environment metadata and compressed file bytes can differ.
Set BLAS thread counts, such as `OPENBLAS_NUM_THREADS=1`, before launch to avoid
multiplying BLAS threads by parent worker count. Memory budgets are **per
worker**; account for all workers in the scheduler's RAM request.

CuPy currently requires `workers=1`; no hidden CPU fallback or automatic GPU
assignment is performed. Candidate batching works with NumPy or CuPy on one
Hamiltonian, and retries only rows that fail the state-error tolerance. If a
norm check fails or a row cannot converge within `max_steps`, generation stops
with an incomplete dataset; it never silently discards a difficult candidate.
Batch per-candidate timing is an explicitly declared equal share of active
batch elapsed time, not an isolated latency measurement. Independent dense
audits remain separate, privileged teacher costs remain separate, and both
must be included in amortization studies.

The authoritative common-bank waveforms are sampled at nine normalized-time
knots, reconstructed, then simulated. Thus the model sees the exact waveform
used for its label, not an approximation of a separately simulated source
schedule. Initial steps must be a multiple of 8 to align with these knots.
Step-doubling state error is a diagnostic, not a rigorous uniform certificate.

An exclusive lock allows only one coordinating writer per dataset, and atomic
record/cache replacement protects against partially written NPZ files. Failed
runs retain complete records and spectral-path caches. `resume=True` checks
configuration, schema, implementation hash, and per-record/cache payload
integrity. Spectral caches are reused without new eigendecompositions; endpoint
arrays may be recomputed for a partially completed parent. Already complete
datasets are audited/read and returned without regeneration.

Lock files retain owning PID and hostname. A crash can leave a stale lock; the
program does **not** guess that a lock on another process or machine is stale.
An operator must verify no active writer exists before removing exactly that
dataset's lock. Never run concurrent writers with separate manifests into the
same record directory. Generation restart after source changes requires a new
dataset directory: existing data remain readable, but silent mixed-source
resumption is rejected.

New records/manifests retain config, implementation, logical-parent and recipe
fingerprints, array-payload digests, plus compressed-file SHA-256 checksums.
The implementation hash covers local package Python source, not its numerical
dependency binaries; the manifest separately records dependency/platform
versions. The loader validates the whole manifest's parent/split relationships
and exact logical fingerprints even when one split is requested, but opens
outcome files **only for that requested split**. Training/validation loading
therefore does not read held-out test outcomes. Selected record contents are
checked against those manifest fingerprints, and escaped paths or incomplete
datasets are rejected. Calling `load_records(root)` without a split explicitly
performs a full-data audit/read. Legacy schema-1 data lacking new checksums and
manifest logical fingerprints are readable with the older guarantees; their
cross-split exact-coefficient audit requires an explicit full-data load. They
cannot be resumed under the new implementation.

These contracts protect reproducibility and leakage boundaries. They do not
establish a useful training distribution or a publishable improvement; those
remain empirical gates in the paper protocol.
